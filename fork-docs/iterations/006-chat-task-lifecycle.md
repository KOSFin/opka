## План и границы апрува

1. Закрепить собственный bundled CLI и профиль Opka для agent child/PTY, не зависеть от глобальной orca и порядка PATH после login shell. Сохранить WSL/SSH/Windows особенности.

3. Переиспользовать существующие task store, attempts/events, session identity и host routing. Обычный чат должен взять/продолжить карточку своей сессией без обязательного нового агента или coordinator Run, с проверкой approval/revision, идемпотентностью и защитой от конкурирующего владельца.
4. Сохранение checkpoint, явного blocker и результата/отчёта по каноническим путям. Карточка показывает попытку и документы. Завершение turn не означает Done; проверка и приёмка отделены от заявления исполнителя.
5. Согласовать обычный чат и кнопку карточки через один lifecycle. Короткий discoverable protocol без загрузки всех инструкций и истории в каждый prompt.
6. Самостоятельная регрессия: обычный чат, повторный запрос, два владельца, рестарт, changed revision, ошибки CLI/host, сохранённый и видимый отчёт, ручное принятие. Тесты, types/quality и hidden UI пропорционально изменениям; реальные модельные turns — только с согласованными аккаунтом/бюджетом.
7. Подготовить отдельную проверенную beta и короткий checklist пользователю. После его проверки собрать поправки. Не объявлять source/unit-проверку испытанием установленного приложения.
8. После надёжного lifecycle сравнить native memory baseline с Engram на отдельных тестовых проектах/профилях. Не менять глобальные hooks/память, не включать облачный ingestion или новые общесистемные службы как побочный эффект.
