## План и границы

1. Воспроизвести reported owning-host terminal identity refusal на настоящем PTY из обычного терминала, без управляемого launchConfig и без кнопки карточки. Использовать отдельный hidden Electron/profile/project и own CLI; исходную released rc.4 не изменять.
2. Отдельно проверить пропажу authority при command env filtering. Не передавать launch secrets через argv, не отключать host/pane/incarnation/owner fences; не выдавать произвольный внешний CLI за терминал Opka.
3. Найти и переиспользовать существующие terminal registration, hook authority, shell wrapper и CLI envelope механизмы. При необходимости добавить минимальный host-owned канал передачи identity с явной совместимостью старых peers, без нового общего auth/scheduler subsystem.
4. Regression gate: обычный и управляемый терминал, повторный claim, чужой owner, неправильный pane/token/host, checkpoint/report→Review, release/reclaim, app restart и stale proof. Folder workspace без Git обязателен; SSH/WSL/Windows сохраняют прежние границы, live серверы не участвуют.
5. Выполнить unit/types/quality и скрытые actual PTY проверки локально до любых сборок доставки. Модель не нужна для deterministic transport regression; настоящий Codex turn потребует отдельного нового согласия. Не называть synthetic child полноценным модельным E2E.
6. Только после зелёного локального gate решать delivery по текущему апруву: точный CI head/aggregate, отдельная immutable beta и released artifact checks. Не использовать публикацию как способ проверить очередную гипотезу. Не менять установленные приложения самостоятельно.

Engram, дизайн, рабочая Orca, оба сервера, глобальные hooks/CLI и корпоративные проекты вне этого среза. Предыдущий append-only журнал итерации6 сохраняется. Пользователь отдельно разрешил один настоящий Codex exec в синтетическом проекте/профиле с текущим входом, без серверов, GitHub, рабочих проектов и дополнительных агентов. До отправки prompt бюджет не использован; после отправки новый повтор требует нового согласия.

## Локальный acceptance gate

- Не только RPC с готовым token: terminal.create без launchConfig → typed shell command → wrapper config → filtered child → actual own CLI → owning runtime.
- Нет secrets в argv/receipt/log; fixture сохраняет только boolean presence, outcomes и синтетические пути.
- Красный тест до исправления и зелёный после; отсутствие модели/сетевого агента явно указано.
- Второй терминал не перехватывает карточку; forged/stale identity не пишет файлы и не создаёт попытки.
- После результата report открывается из карточки, статус Review, Done только после operator decision.
