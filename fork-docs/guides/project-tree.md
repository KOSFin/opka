# Дерево проектов

## Где работать

Левое меню организовано по месту выполнения, а не по задачам:

```text
LOCAL MAC                         ← раздел компьютера, стрелка сворачивает его целиком
  Career              New chat    ← общая папка проекта; имя открывает, New chat запускает агента
    Project session                ← сохранённое место для файлов/терминалов/агентов
    apps/web                       ← самостоятельный репозиторий; подпись — путь в проекте
        Main workspace            ← исходная рабочая папка для чатов/файлов
          Branch main             ← текущая Git-ветка этой папки
        fix-login                  ← другая рабочая копия этого же репозитория

BUILD SERVER                      ← отдельный раздел удалённого хоста
  Другой проект
```

Это схема, не автоматически создаваемые названия. Ручные имена проектов и рабочих копий сохраняются. Сервер — не проект; `apps/services` — не отдельные проекты; ветка — не отдельный репозиторий. Worktree — отдельная рабочая папка того же Git-репозитория со своей выбранной веткой.

Внутри импортированного проекта показан список репозиториев по относительным путям, без промежуточных папок: `apps/web`, `services/backend`, `embedded`, `embedded/module`. `embedded` и `embedded/module` — два самостоятельных репозитория, не две ветки. Надписей Git/Root Git больше нет. Физическое дерево каталогов доступно во вкладке Files. Общая папка проекта не обязана иметь `.git`; приложение не создаёт его и не объединяет истории вложенных репозиториев.

Проекты отделены полосой заголовка, хосты — сворачиваемыми разделами. **New chat** находится у правого края строки; `…` и `+` появляются слева от него при наведении/фокусе без сдвига. У репозитория компактная кнопка с диалогом и плюсом запускает чат только для него. Меню выбора агента само не запускает shell или агента; запуск происходит после выбора. `Project session` хранит вкладки общего проекта, `Main workspace` — вкладки конкретного репозитория. Это места работы, а не отдельные задачи доски.

## Общий Source Control

Откройте общий проект и вкладку **Source Control** справа. Сверху расположен компактный список репозиториев; ниже — изменения, staging, сообщение коммита и история только выбранного репозитория. Одновременно работает одна Git-панель, без вертикального набора полноразмерных копий и вложенных общих скроллов. Выбор репозитория не переключает текущий чат и не создаёт терминал. Commit draft хранится отдельно у каждой рабочей копии. Если копий несколько, есть их селектор — выбор не меняет ветку в других папках. Историю можно свернуть или изменить её высоту за разделитель **Commits**; поддерживаются также клавиши у **Resize commits**.

Нажатие на изменённый файл показывает его diff в соответствующей рабочей копии, не создавая запасную консоль. В **Commits** раскройте нужный коммит: автор, время и файлы показываются под ним; нажатие файла открывает commit diff. Staging/commit касаются только выбранного репозитория/копии. Общего коммита сразу во все репозитории нет.

При переключениях внутри работающего приложения сохраняются раскрытые секции/коммиты, высота истории, прокрутка, фильтр и выбранная копия. Это ограниченная renderer-память, не восстановление всех настроек после перезапуска. Свежая история переиспользуется до 30 секунд; при обновлении остаётся предыдущий результат. Refresh, Git-операции и смена HEAD/base запрашивают актуальные данные. Отключённый сервер не заменяется чтением локальной папки.

Вкладка **Attached worktrees** остаётся отдельной: это рабочие копии, созданные из общей сессии (например, для исполнителей), а не каталог всех репозиториев и не вторая Git-панель.

## Задачи рядом с чатом

В **Tasks → Project tasks** нажмите **Open beside chat**: основной workspace вернётся на экран, а доска появится в существующей плавающей панели. Её можно передвигать, менять размер, разворачивать и сворачивать. Кнопка **Workspace / Project tasks** в заголовке переключает содержимое; прежние floating-вкладки не закрываются. Нижняя правая кнопка возвращает свёрнутую панель. Карточка открывается прямо внутри неё; **Back to board** возвращает к доске с проверкой несохранённых правок. Черновик сохраняется при сворачивании/переключении в рамках работающего приложения; перед выходом из приложения используйте **Save plan**.

Полноэкранная доска остаётся доступной, колонки используют те же статусные цвета, что Working copies. Выбор проекта/All projects сохранён; отдельной привязки задачи к одному репозиторию не требуется.

## Что означает Working copies

Это существующая доска **рабочих папок**, а не проектных задач. Её карточка открывает рабочую копию с файлами и вкладками агентов. Перенос карточки меняет только организационный статус этой копии: он не переключает Git-ветку, не делает commit/merge и не завершает проектную задачу. Колонки/иконки помогают группировать текущую работу.

Опция **Sync linked Linear issue status** относится к связанной задаче **Linear**, если интеграция настроена и найдено соответствующее состояние workflow. Это не синхронизация GitHub Issues/GitLab/Kaiten и не проверка результата кода. По умолчанию для нового workflow пользуйтесь **Project tasks** для цели, плана, журнала и приёмки, а Working copies — при необходимости для организации исполнения. Их статусы намеренно не связаны автоматически: завершённая консоль или перемещённая копия не доказывает выполнение задачи.

Для задачи сразу по backend/frontend нажмите **New chat** у общего проекта и выберите своего агента. Он получает общую папку, содержащую все репозитории. Чтобы открыть сохранённые вкладки, нажмите название проекта: существующая общая сессия переиспользуется, а при её отсутствии регистрируется автоматически, без Create folder workspace. Начальная вкладка пустого workspace зависит от настроек Orca; название проекта не создаёт Git-репозиторий или ветку и не запускает задачу с доски.

У репозитория кнопка с пузырём чата открывает тот же launcher в его основной рабочей копии. Название репозитория открывает эту копию; общий Source Control сохраняет соседние репозитории и раскрывает выбранный. **New chat не создаёт изолированную ветку**. Для параллельной реализации сначала создайте дополнительную рабочую копию существующим действием в меню/плюсе репозитория, затем запускайте агента в ней.

Стрелка проекта/папки/repo только сворачивает дерево, не меняя выбранное место работы и не завершая агентов. Обычная промежуточная папка раскрывается по имени. Перетаскивание выполняется только за отдельную ручку, не за название; меню сохраняет переименование и удаление. Выбор агента и модели остаётся штатным, ничего не зашито в New chat.

Чат — сессия Codex/Claude внутри выбранной рабочей папки, не ветка Git и не карточка задачи. Несколько чатов могут работать в одной копии; для конкурентных правок нужна изоляция. Историю хранит существующая агентная интеграция, новой базы чатов этот экран не создаёт.

Разделы хостов выделены отдельной полосой с границами. В дереве проектов заголовки прокручиваются вместе со строками, не закрепляются друг поверх друга. Стрелка есть только у строки с содержимым; она также работает с клавиатуры. Старые пустые folder-scan дубли того же пути/родителя/хоста скрыты только в представлении: занятые и ручные группы, ветки и чаты не удаляются.

У общей папки не обязано быть `.git`. В её Source Control показываются зарегистрированные репозитории проекта на том же хосте. Раскрытие секции показывает changes/commits/branches без ухода из общего workspace; переход к файлу уже открывает нужную копию. Общего коммита сразу на все репозитории нет; фиктивный Git root не создаётся. Папки, Git-репозитории и история не переносятся ради отображения дерева.

Tasks — отдельно: принятая доска результатов и планов. Рабочие копии — места выполнения этих задач, а не ещё одна доска задач. Подробный сценарий: [работа с задачами](vibe-coding-workflow.md).

## Как добавить несколько репозиториев

В Add Project выберите через Browse общую папку, которая сама не является Git-репозиторием. В обзоре найденных репозиториев проверьте относительные пути, выберите нужные и импортируйте группой. Режим импорта отдельными проектами также сохранён.

Промежуточные scanned-каталоги не занимают отдельные строки слева: вместо services → payments → api показан `services/payments/api`. Репозитории сохраняют независимые ветки и рабочие копии. Проект и копии можно сворачивать; rename/delete/create остаются в прежних меню. Существующие ручные группы сохраняют организацию.

Повторный импорт той же папки использует уже созданные folder-scan группы на том же хосте. Он не дублирует их и не сбрасывает имена, свёрнутость или ручной порядок уже размещённых проектов. Ручные группы не подменяются автоматически.

## Что ограничено

- По умолчанию scanner ищет до трёх уровней и до 100 репозиториев; сохраняются ограничения времени, gitignore и исключения dependencies, symlinks и Git metadata. Это не неограниченный обход диска.
- Внутри найденного non-bare Git repository поиск продолжается; .git-файлы также распознаются. Внутренний optional параметр includeNestedRepos=false оставляет прежний sibling-only обход.
- Выбор самого Git root по-прежнему быстро добавляет один проект. Для обзора нескольких репозиториев выбирайте общую non-Git папку.
- Импортированная структура и IDs сохранены на диске; sidebar упрощает только представление. Автоматические container-группы не становятся лишними проектами. Ручные группы не сворачиваются этим projection.
- Репозиторий, добавленный отдельно, может находиться прямо под хостом без общей папки проекта. В тестовом профиле Remote tree, embedded и Fork audit workspace — имена учебных примеров, не специальные функции или embeddings. Такие примеры и их сохранённые сессии не удаляются ради внешнего вида.
- Ручные и уже вложенные группы не перестраиваются на загрузке. Существующая адаптация старых плоских folder-scan групп использует полное дерево и сохраняет идентификаторы проектов.
- Desktop/mobile используют общую модель дерева; проверены её тесты и remote runtime. Отдельная приёмка на Android ещё не выполнена.
