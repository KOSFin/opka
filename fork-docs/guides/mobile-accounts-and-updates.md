# Аккаунты, мобильная работа и обновления Opka

## Сначала выберите хост

Проекты, процессы агентов, входы провайдеров и пулы принадлежат компьютеру или серверу, на котором выполняется работа. В desktop Settings выберите Host; на телефоне откройте нужный сервер. Переключение между локальным и серверным workspace меняет контекст Usage. Оно не переносит авторизацию между машинами.

Desktop и телефон могут управлять одним сервером независимо. Закрытие клиента не завершает серверную задачу. При потере связи состояние выполнения нельзя считать завершённым: дождитесь восстановления соединения.

## Обычный CLI-вход и сохранённый профиль

**CLI login on this host / Normal CLI login** — существующий вход обычного CLI на выбранном хосте. Это источник авторизации, который пользователь может изменить вне Opka. Он не является автоматически сохранённым участником пула.

**Saved profile** — отдельный контекст входа, добавленный через штатный вход провайдера в Opka. Его можно выбрать для новых ручных чатов или включить в пул. Чтобы использовать аккаунт в пуле, добавьте сохранённый профиль; копировать файлы с токенами вручную не нужно.

Одинаковый email у CLI-входа и сохранённого профиля не означает две подписки или два независимых лимита. Организация, workspace и runtime помогают различать контексты. Opka не суммирует их как независимую доступную ёмкость.

**Use for new chats** меняет значение по умолчанию для новых ручных запусков. Уже открытый чат сохраняет назначенный аккаунт. Выбор провайдера и выбор аккаунта внутри провайдера — разные действия.

## Когда нужен пул

Для одного аккаунта можно оставить пул выключенным. Все обычные функции ручного выбора продолжают работать.

В секции Accounts Pools раскройте нужного провайдера. Включение применения пула относится к новым поддерживаемым чатам и workers на этом хосте. Режим автоматического переключения задаётся отдельно. При смене аккаунта активные инструменты, запросы разрешений и текущая работа должны завершиться до безопасного перехода.

Приоритет, вес и состояние участника задают правила выбора. Резерв используется только при соответствующем разрешении и отсутствии подходящего основного участника. Исключённый участник не получает новых назначений. Неизвестный лимит не означает ни нулевой расход, ни свободную подписку: разрешение таких аккаунтов — явная настройка политики.

Сохраните настройки конкретного провайдера и дождитесь подтверждения хоста. Черновик сохраняется при сворачивании секции и переключении Accounts / Pools. Переход на другой хост не должен переносить туда старый черновик.

## Usage и закрепления

Откройте Usage в нижней панели: список показывает источники CLI и сохранённые профили текущего хоста, доступные лимиты, сбросы, принадлежность к пулу и его параметры. Чтение списка не переключает авторизацию. Подробности и действия сброса доступны в меню провайдера.

Кнопка закрепления добавляет аккаунт в компактную нижнюю панель. Показываются до трёх закреплений текущего хоста и счётчик остальных. Это только настройка отображения, без изменения пула или аккаунта чата. Удалить недоступное закрепление можно в списке закреплений.

Процент соответствует выбранному способу отображения расхода. Прочерк означает отсутствие подтверждённых данных. Старые данные помечаются отдельно. При смене аккаунта Opka не должна подписывать его именем лимиты прежнего профиля. Старый сервер без подтверждения источника может показывать неизвестный активный лимит до обновления; записи с точным ID сохраняют совместимость, если их метаданные не противоречат этому ID.

## Телефон: проекты и карточки

Структура начинается с проекта, затем показывает его репозитории и рабочие места. Отдельные репозитории старых хостов остаются доступны. Настройки раскрытия и видимости используют существующий контекст хоста.

Списки, доска и детали MR сохраняют ограниченные результаты в памяти. Повторное открытие использует свежий результат; устаревшее представление обновляется, сохраняя читаемый экран. Явное обновление требует нового чтения. Смена владельца, ревизии или мутация прекращает использование неподходящих данных. Отчёты и тела карточек не записываются в настройки UI.

Проектную карточку можно создать, открыть, отредактировать и переместить через доступные действия. Заголовки фаз имеют отличимые иконки. Перемещение не заменяет принятие результата: Done остаётся частью отдельного действия Accept. Устаревший план или сменившийся сервер требуют повторного открытия актуальной карточки.

Для GitLab сохраняются выбранные представление, фильтр и запрос в пределах мобильной сессии данного хоста. Они не отправляются неизвестными полями старому серверу. MR показывает доступные сведения об авторе, ветках, проверках, согласованиях, участниках и файлах. Отсутствующие поля старого хоста обозначаются как недоступные. Наличие сведений не включает автоматически действия merge или изменения review.

Короткие переходы выполняются только при пользовательском переключении раздела; серверное обновление данных не запускает анимацию заново. Reduced motion отключает движение.

## Android-обновление

Баннер и Settings используют один механизм загрузки с состоянием и ошибками. Android может сначала потребовать разрешить установку из Opka, затем подтвердить замену приложения. Это штатное подтверждение ОС.

APK проверяется по размеру, SHA256, имени пакета, версии и сертификату подписи. Повторная попытка может использовать уже скачанный файл, но проверяет его снова. Файлы установщика неизменяемы, пока Android может читать их URI; число ожидающих APK ограничено. После успешной установки очищается кеш обновления, включая совместимый старый формат. Повреждённый файл не должен блокировать последующую загрузку навсегда.

Проверка будущего updater и проверка перехода с уже опубликованного старого APK — разные сценарии. Выпуск должен опираться на результаты обоих; если старый установленный клиент сам не способен открыть установщик, восстановление требует отдельной установки исправленного APK.

## Уведомления и проверка расхода

Собственный Android package использует собственную Firebase-конфигурацию. Отправляющая серверная учётная запись хранится отдельно от APK и исходников. Разрешение уведомлений, получение токена, регистрация на хосте и фактическая доставка — разные этапы; успешная сборка не доказывает доставку.

Замеры CPU, памяти, кадров и сетевых счётчиков на эмуляторе помогают найти регрессии. Они не измеряют физический расход батареи Xiaomi и не доказывают отсутствие всех утечек. Результаты должны указывать версию APK, сценарий, длительность, доступность метрик и ограничения сравнения.
