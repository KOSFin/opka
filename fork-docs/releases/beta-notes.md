Opka — экспериментальный форк Orca, не официальный релиз Orca.

Исправлено взятие карточки из обычного терминального Codex, запущенного вручную, а не кнопкой карточки. Терминал получает подтверждённую владельцем привязку к процессу; фильтрация окружения Codex больше не теряет её. Также исправлен случай `codex exec … -c …`, в котором настройки команды отбрасывали переданный CLI. После обновления откройте новый терминал/чат: уже работающий процесс не получает новое окружение задним числом. Существующие терминалы не завершаются принудительно.

Открытие и отмена меню «Новый чат» больше не активирует пустой проект и не провоцирует запуск лишнего терминала. Проект раскрывается после выбора агента, когда его вкладка уже создана; тот же порядок сохранён для встроенного чата.

Если установлена rc.1 или rc.2, скачайте новый DMG напрямую из Assets GitHub Releases и проверьте SHA256SUMS. В этих старых версиях Electron отменяет перенаправление при встроенном скачивании; их binary не может исправить себя до замены. В этом выпуске загрузчик использует существующий проверяемый streaming transport вместо net.fetch с manual redirect; ограничения GitHub HTTPS и checksum сохранены.

- Mac arm64: `opka-macos-arm64.dmg`; ZIP предназначен для проверки release feed и переносимой установки.
- Linux x64: `opka-server-linux-x64.tar.gz` содержит runtime, Node и нативные зависимости. После распаковки запускайте `./opka-server`; по умолчанию доступ только через loopback. Для обычного подключения по SSH используйте встроенную установку runtime из Opka.
- `SHA256SUMS` и provenance JSON позволяют проверить целостность файлов и исходный коммит. Контрольная сумма не заменяет подпись разработчика.

Mac beta не имеет Developer ID и notarization. macOS может запросить явное разрешение на открытие приложения. Не отключайте Gatekeeper и не снимайте quarantine скриптами. Обновление: скачать установщик из Opka, дождаться проверки, открыть его, завершить только Opka и подтвердить замену `Opka.app`. Не заменять `Orca.app`. Данные профиля не входят в пакет и не удаляются при замене приложения.

Это ещё не production-релиз. Не используйте beta для единственной копии важных данных. Рабочая Orca, её профили и старые серверы не являются целями установки. Аккаунты автоматически не переносятся. Автоматическая регистрация user-global hooks отключена: Codex и управляемые аккаунты устанавливают hooks в собственные runtime homes; существующие настройки глобальных CLI не переписываются при старте.

В этом выпуске: обычный чат Opka может взять утверждённую карточку своей сессией, сохранять checkpoint/препятствия и отправить отчёт на Review. Отчёты доступны в карточке через Reports & notes. Done требует отдельной приёмки пользователя. Непривязанный внешний CLI не получает identity автоматически.

Настройка интеграции перенесена из карточки в **Tasks → Board settings**. Она включена по умолчанию для новых проектов и при открытии доски существующего проекта. Переключатель показывает Enabled/Disabled либо неполную/изменённую установку; отключение сохраняется после перезапуска. Изменённые пользовательские навыки и AGENTS.md сохраняются. После изменения настройки или обновления откройте новый чат/терминал: окружение уже запущенного Codex задним числом не меняется.

Исправлен пропущенный ORCA_CLI_COMMAND в общей терминальной обёртке Codex: она передаёт собственный CLI через командную политику окружения, как уже делал встроенный чат. Изменённые shell wrappers имеют новую совместимую версию terminal daemon; существующие терминалы не завершаются принудительно. Пользовательский явный отказ от изоляции/фильтры окружения не отключаются.

Исправлены выбор собственного CLI в терминалах, поиск задач из вложенной папки без Git и проверка обновлений при отсутствии более нового prerelease. При выборе ранее ненастроенного проекта доска перепроверяет каталог; уже настроенные переключения не получают нового полного сканирования.

Заключительный настоящий Codex turn в изолированном проекте прошёл полный локальный сценарий: обычный терминал → взятие карточки → исправление кода → тесты → checkpoint/report → Review → открытие отчёта после перезапуска. До этого два воспроизводимых отказа были исправлены и сохранены в журнале. В обязательный CI добавлена проверка настоящего бинарника Codex с локальными сценарными ответами — без аккаунта и платной модели. Отдельно проверяются конкурирующий владелец, освобождение/повторное взятие и продолжение после перезапуска. Это не доказательство всех агентных сценариев. Независимый AI-reviewer, автоматический Done, передача недоступного владельца и Engram не входят в выпуск. Полная E2E проверка типов содержит grandfathered ошибки; это не stable-релиз.

Версию, выполненные проверки и ограничения сверяйте с журналом итерации 7 и руководством fork-docs/guides/chat-task-lifecycle.md в исходниках этого релиза.
